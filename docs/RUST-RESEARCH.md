# Rust / Tauri build audit — 2026-11-24

The development sandbox has **no Rust toolchain and blocks crates.io**, so
`cargo check` could not be run there. Instead, every uncertain construct in
`src-tauri/` was verified against **primary sources** (Tauri / reqwest / rfd /
serde_json repositories via the GitHub API) and the official docs. This file
records what was checked, what failed, and what was fixed.

## Issues found & fixed

| # | Issue | Evidence | Fix |
|---|-------|----------|-----|
| 1 | `send_chat` takes one struct param (`req`), but the frontend passed the fields **flat** — Tauri binds arguments **by key**, so invoke fails with `missing required key req` | [Tauri: Calling Rust](https://v2.tauri.app/develop/calling-rust/); [users.rust-lang.org thread](https://users.rust-lang.org/t/unable-to-invoke-tauri-command-with-struct-argument-from-yew-frontend/95814) | `bridge.ts` now sends `{ req: { model, baseUrl, apiKey, messages } }`; mock mirrors the shape |
| 2 | `rust-version = "1.77.2"` — Tauri v2's workspace floor is **1.90** (`tauri-cli` Cargo.toml) | tauri repo root `Cargo.toml` (`rust-version = "1.90"`) | bumped to `1.90`; README requires Rust ≥ 1.90 |
| 3 | `String::truncate(200)` **panics** if index is not a char boundary — agent output with CJK/emoji would crash the command | Rust std docs for `truncate` | char-based `chars().take(200).collect()` in `humanize_line` |
| 4 | Prompt passed as argv through `cmd /C` (npm `.cmd` shims) — cmd.exe mangles `&`, `^`, `%VAR%` in the command line | Windows cmd parsing semantics | Claude Code now receives the prompt **via stdin** (`claude -p` with no positional reads stdin); opencode keeps argv, documented as a V4 concern |
| 5 | Stale pid in the agents map if a later `?` failed after registration (kill-by-pid could hit a recycled pid) | code review | stdio pipes are taken **before** the map insert |
| 6 | `panic = "abort"` in release profile — not what the Tauri template/ecosystem assumes | Tauri app template parity | removed |
| 7 | `save_settings(settings: settings::AppSettings)` — param name == module name used in `settings::save(...)` expression path; single-segment/local shadowing is a known rustc hazard (E0618 class) | Rust reference on path resolution; shadowing issues on GitHub | module imported as `app_settings` alias — zero ambiguity |

## Verified OK (no change needed)

- **Command names** must be the exact Rust fn name: tauri-macros uses
  `RenamePolicy::Keep` + `stringify!(ident)` → JS invokes `get_settings`,
  `run_agent_prompt`, … (snake_case). *Source: `crates/tauri-macros/src/command/{wrapper,handler}.rs`.*
- **Argument keys** default to camelCase on the JS side
  (`argument_case: ArgumentCase::Camel`) → `{ sessionId }`, `{ baseUrl }`,
  `{ apiKey }` are correct.
- **`Manager::path()` + `app_config_dir()`** exist in Tauri 2
  (`crates/tauri/src/lib.rs`, trait `Manager`, `fn path()`).
- **`Emitter::emit`** — payload `Serialize + Clone` ✓ (`AgentLine` derives both).
- **reqwest 0.12 features** — `json` and `rustls-tls` exist on the `0.12.x`
  branch; `rustls-tls` → `rustls-tls-webpki-roots` → `__rustls-ring` (**ring**,
  not aws-lc-rs → no cmake/NASM surprise on Windows). `default-features = false`
  is fine for local HTTP + optional HTTPS.
- **rfd** — repo is `PolyMeilex/rfd` (note the spelling); `0.15` exists
  (0.15.4). API used (`AsyncFileDialog::new().set_title().pick_folder()` →
  `FileHandle::path()`) is present and stable; kept `rfd = "0.15"` because
  0.18's MSRV is 1.92 (above Tauri's 1.90 floor).
- **Capability permissions** — `core:default`, `core:event:default`,
  `core:window:default` all exist (default permission sets documented in
  `crates/tauri/permissions/*/autogenerated/reference.md`); `listen` is in the
  event default set, so the `agent-line` subscription is allowed.
- **App-command ACL** — `tauri-build` only filters app commands when the app
  defines its own manifest (`has_app_manifest` from `app_manifest_permissions`);
  we don't, so all 8 commands register (`handler.rs`: no ACL → no filtering).
- **`tauri.conf.json` schema** — checked field-by-field against
  `crates/tauri-utils/src/config.rs`:
  - `$schema` is a real field;
  - `bundle.windows.webviewInstallMode` = `WebviewInstallMode` with
    `#[serde(tag = "type", rename_all = "camelCase")]`, `silent` defaults;
  - `bundle.windows.nsis.installMode = "currentUser"` — `NsisConfig` is
    `camelCase` + `deny_unknown_fields`, `install_mode` has `#[serde(default)]`,
    all other fields are `Option` → partial config valid;
  - `bundle.targets = ["nsis"]` is a documented target;
  - window keys (`minWidth`, `minHeight`, …) are standard `WindowConfig`.
- **`serde_json::json!` dynamic keys** — docs: "any type interpolated into an
  object key must implement `Into<String>`" → `"models": { model: {…} }` is
  valid (used in the generated OpenCode config).
- **Command uniqueness** — the8 command names are unique across modules
  (Tauri requires global uniqueness).
- **Partial moves in `send_chat`** — `req.model` moved into `json!` while
  `req.messages`/`req.api_key` are borrowed/used later: legal field-disjoint
  borrows.
- **No `MutexGuard` held across `.await`** in `run_agent_prompt` (would make
  the command future non-Send) — all lock scopes are synchronous blocks.
- **tokio features** — `process`, `io-util`, `sync`, `rt-multi-thread`,
  `macros`, `time` cover everything used (`mpsc`, `Child`, `AsyncWriteExt`).
